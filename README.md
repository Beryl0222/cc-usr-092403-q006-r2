# 老红橘保护性收购

广兴镇老红橘接入饮料企业原料链后的收储结算与溯源服务：追踪地块、老树群、
管护记录、采收批次、检验等级、企业交货四条线的连续关系，并在并发与断网
场景下保证「每公斤果实只结算一次、保护树不越界、价格不回溯」。

在正向收购链之外，另覆盖**农残复核异常触发的多节点召回**：异常往往在分级、
加工甚至结算之后才暴露，同一来源的货一部分在库、一部分在途、一部分已成成品，
召回可从地块、过磅批次、加工批次或成品任一节点发起，沿父子数量关系定位当前
保管方分别处置，确认受影响后以追加账处理暂缓/追回/恢复，结案时交代数量守恒、
未回执节点与每笔资金。

## 领域模型与连续溯源链

```
农户 ─ 地块 ─ 树群(普通老树/百年保护树)
                │  管护记录（含护树队病害上报）
                ▼
            采收批次（保护树先预占配额）
                │  过磅单（批次+流水号幂等，断网可重传）
                ▼
            检验样本（初检定级、封存留样；农残复核可另起）
                ▼
            企业交货（锁定交货时适用价规版本）
                │   ├─ 在库 ─┐
                │   ├─ 在途（承运）┤
                │   └─ 到厂加工 → 加工批次 → 成品(在库/在途/已交付)
                ▼
            农户结算（逐磅单计价固化）
                │
   ┌────────────┼─────────────┐
   ▼            ▼             ▼
企业退货     运输损耗      果肉加工路线
（独立流水） （独立流水）    （陈皮等，独立流水）

农残复核不合格 ──▶ 召回单（地块/过磅批次/加工批次/成品 任一节点发起）
                     │  范围版本（扩大补建 / 缩小保留人工隔离）
                     ▼
              处置任务（定位当前保管方）→ 隔离/拦截/退回/销毁/解除/替代交付
                     │  冲突待授权复核；通知/回执幂等（离线可补录）
                     ▼
              追加账（暂缓/追回/恢复）+ 守恒结案报告
```

## 强制不变量（由 `domain.py` 校验，测试逐条证明）

1. **同一批果不重复结算**
   - 过磅单按 `(批次, 过磅流水号)` 幂等：断网地磅恢复后重传纸质磅单只返回原单，
     不二次入库（含 8 线程并发同号提交测试）。
   - 结算以未结算磅单为粒度，已结算磅单被结算单永久引用；并发结算第二次返回
     `already_settled`。
2. **保护树采收不越界**：百年保护树按采收季下达重量+次数配额；采收前按批次
   预占（跨批次汇总核额），过磅回冲预占，超采当场拒绝；无配额不得采收。
3. **价格不回溯**：合约记录签约时价规版本；交货时锁定当时适用价规，应收金额
   随结算固化。之后市场价涨跌只能发布价规新版本，历史结算分文不改。
4. **复核留痕与价差**：质量复核改级时，原检验记录与封存样本保留（标为非现行），
   新记录标注「复核自」。结算前改级按新等级计价；结算后改级另出**价差调整**
   （补付/扣回），不覆盖原结算行。
5. **四条独立流水**：农户结算 / 企业退货 / 运输损耗 / 果肉加工分账；退货不冲减
   农户应收；数量勾稽 `退货 ≤ 到货 ≤ 交货核定`，加工投入不得超过来源可处置量。
6. **护树队最小权限**：只能上报病害/违规采摘、查看裁剪后的树群视图；结算、
   账本、批次、过磅、反查一律 403。
7. **成品原料反查**：企业可从交货单或陈皮加工路线反查地块、树群、管护记录、
   历次检测依据（含样本编号）与实际受益农户；只能反查本企业的交货单。

## 农残复核与多节点召回（由 `domain.py` 校验，测试逐条证明）

8. **农残复核不可改写原始检验**：农残复检只追加记录、标注「复核自」并沿用封存
   样本，不改变质量等级、不产生价差；原检验与历史结算保持原样，**仅「不合格」
   记录**可作为发起召回的异常依据。
9. **任一节点发起 + 范围版本**：召回可从**地块、过磅批次、加工批次、成品**任一
   节点发起，沿父子数量关系把范围展开为当前保管方处置单元（在库企业、在途承运、
   到厂/成品加工方、已交付客户企业、退货持有），每次扩/缩都生成不可丢的范围版本。
   从成品/加工批次发起只追该成品，不顺手并入同交货单尚未投入的余量。
10. **扩围补建、缩围不自动释放人工货**：扩大范围取并集补建任务；缩小范围时，
    系统隔离货自动解除，但**已被人工隔离/拦截/退回/销毁的货不自动释放**，转为
    「出围待核」继续物理冻结，须人工销毁或解除；重新纳入时人工冻结货仍保持冻结。
11. **通知与回执只产生一次业务效果**：召回通知按任务幂等；处置回执按
    `(任务, 回执流水号)` 幂等，**离线补录与重复推送**重放只返回原回执。
    销毁必须先隔离/拦截；替代交付仅成品可用；处置重量受任务量约束。
12. **冲突等待授权复核**：现场数量/归属/结论冲突挂「待授权复核」，裁决前任务
    冻结、不能处置也不能结案；监管裁决维持隔离或解除隔离，解除联动**自动恢复**
    该农户尚未解除的暂缓/追回挂账。
13. **追加账与等级申诉一致**：确认受影响后以**追加账**记录暂缓、追回、恢复，
    原始结算行与历史结算分文不改；挂账上限＝原合计＋全部等级价差后的当前权益，
    恢复不得超过未解除挂账。农户最终权益＝原结算＋等级价差＋召回追加账。
14. **守恒结案**：结案必须同时满足数量守恒
    （在隔离＋未处置＋销毁＋退回＋替代交付＋解除＝范围总量）、无未回执节点、
    无未终态任务、无缩围后仍人工冻结货、无待裁决冲突；报告逐笔列出每笔资金的
    暂缓/追回/恢复与按结算净额，结案后召回冻结。
15. **召回数据最小化**：护树队对召回一律不可见；农户只见挂到本人的原料节点与
    本人追加账；企业只见本企业在库/在途节点、不见成品与资金；加工方只见在制/
    成品节点；跨企业互不可见；跨方守恒结案报告仅监管与合作社可见。

## HTTP 接口

除 `GET /health` 外均需 `X-Actor-Token` 头，JSON 收发；业务错误返回
`{"error": 代码, "message": ...}`（401/403/404/409/422）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/actors` | 登记身份令牌（角色：果农/合作社/质量复核人/护树队/收购企业/加工方/监管人员） |
| POST | `/farmers` `/plots` `/trees` | 农户、地块、树群建档 |
| POST | `/quotas` | 保护树按季配额（重量+次数） |
| POST | `/cares` `/reports` | 管护记录；护树队上报病害/违规采摘 |
| POST | `/batches` `/reservations` | 开立采收批次；保护树额度预占 |
| POST | `/weigh` | 过磅（支持毛重/皮重、断网标记；批次+流水号幂等） |
| POST | `/inspections` `/reviews` | 初检定级封存样本；复核改级 |
| POST | `/price-rules` `/contracts` | 发布不修改的价规版本；签约锁定基准价规 |
| POST | `/deliveries` `/settlements` | 交货锁价；合作社逐磅单结算 |
| POST | `/returns` `/losses` `/processing` | 退货 / 损耗 / 陈皮等加工三条独立流水 |
| POST | `/pesticide-reviews` | 农残复核（不改原检验；仅不合格可召回） |
| POST | `/processing-ship` `/processing-arrive` | 原料 在库→在途→到厂 |
| POST | `/processing-batches` `/goods-ship` `/goods-deliver` | 加工批次建档出成品；成品发运/交付 |
| POST | `/recalls` | 从 地块/过磅批次/加工批次/成品 发起召回（首版范围） |
| POST | `/recall-reshape` | 范围改版（扩大补建 / 缩小保留人工隔离） |
| POST | `/recall-notify` `/recall-receipts` | 通知（幂等）；隔离/拦截/退回/销毁/解除/替代交付回执（离线可补录、幂等） |
| POST | `/recall-conflicts` `/conflict-resolve` | 上报冲突待授权复核；监管裁决 |
| POST | `/recall-funds` | 追加账：暂缓 / 追回 / 恢复（不改原始结算） |
| POST | `/recall-close` | 监管守恒结案（数量勾稽+回执+资金齐全） |
| GET | `/batches` `/batches/{id}` `/trees/{id}` | 链上查询（按角色裁剪） |
| GET | `/settlements/{id}` | 结算单（含价差调整） |
| GET | `/ledgers/{农户结算|企业退货|运输损耗|果肉加工}` | 分账导出 |
| GET | `/trace?delivery=…` 或 `?route=…` | 成品原料反查 |
| GET | `/recalls` `/recalls/{id}` `/recalls/{id}/report` | 召回列表 / 详情（按角色裁剪）/ 守恒结案报告（仅监管、合作社） |

## 运行与测试

```bash
python3 service.py --check     # 基础配置检查
python3 service.py --port 8000 # 启动服务
npm test                       # 60 个用例：契约 + HTTP 集成 + 领域不变量（含并发/召回）
python3 -m compileall -q .     # 编译检查
```

## 文件

- `domain.py` — 领域对象、四流水、农残复核与多节点召回及全部不变量
  （线程安全，内存存储）。
- `service.py` — HTTP 适配层与路由，不含业务规则。
- `test_domain.py` — 48 个领域用例，含断网重放、并发过磅/结算/申诉、
  保护树配额、价差方向、价格不回溯、反查链，以及农残复核、多节点发起、
  范围扩缩（人工隔离不自动释放）、离线回执幂等、冲突授权裁决、退回持有、
  替代交付、追加账与等级申诉一致、守恒结案、四类角色数据最小化。
- `test_api.py` — 9 个 HTTP 用例，验证鉴权、错误码、端到端流程与召回
  全链路（含角色边界与冲突冻结）。
- `service_contract.py` — 健康检查与路由暴露的原始契约。
- `fixtures/domain.json` — 统一领域称谓、召回处置动作与不变量清单。
